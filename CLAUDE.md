# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Python script that recursively scans a source folder for `.mkv` files, identifies each one as a movie or TV episode (via TMDb/TVDB lookups), and converts it with `HandBrakeCLI` into an `.mp4` written into a Jellyfin-style destination tree (`movies\Title (Year)\...` / `shows\Show\Season NN\...`).

## Commands

```
pip install -r requirements.txt   # guessit, requests, python-dotenv, rapidfuzz
cp .env.example .env              # then fill in the values below
python src/main.py "C:\Video"     # run the pipeline over the folder given
python src/main.py                # same, falling back to SOURCE_DIR in .env
```

Tests are pytest under `tests/`; run them with `python -m pytest`. There is no build step.

Required `.env` values (see `.env.example`): `DEST_DIR`, `HANDBRAKE_CLI_PATH` (blank = search PATH), `HANDBRAKE_PRESET` (must exactly match a name from `HandBrakeCLI --preset-list`), `TMDB_API_KEY`, `TVDB_API_KEY`. `SOURCE_DIR` is optional and acts as the fallback when no folder is given on the command line.

## Dev tooling

```
pip install -r requirements-dev.txt   # pylint, pydocstyle, pycodestyle, black, isort, mypy
python lint.py                        # auto-fixes (isort, black), then checks (pycodestyle, pydocstyle, pylint, mypy)
```

Every `.py` file must pass `python lint.py` cleanly before any commit — this is manual discipline (there's no git hook or CI wired up), not an automated gate. Docstrings are Google-style and required on every public module, class, and function (`pydocstyle`-enforced); private (`_`-prefixed) helpers don't need one. This project's assistant never runs `git push` — only the user pushes.

## Architecture

Pipeline, orchestrated by `main.py`, one file processed at a time (sequential by design — HandBrake already saturates all CPU cores per job):

1. `config.py` — loads and validates `.env` into a frozen `Config`; resolves `HandBrakeCLI` path (explicit `HANDBRAKE_CLI_PATH` or PATH lookup via `shutil.which`). The source folder is the one setting that doesn't belong in `.env`: it changes from run to run (`C:\video` → `E:\Video` → `C:\Video` so far), and a stale value is the worst failure mode available — the scan finds nothing, every tally reads zero, and the run exits 0 as though it had succeeded. So `main.py` takes it as an optional positional argument, `load_config(source_override)` prefers that over `SOURCE_DIR`, and `_resolve_source_dir()` errors naming both routes when neither is given. `SOURCE_DIR` survives only as the fallback.
2. `discfolder.py` — handles ripped-disc libraries, where the filename is an opaque track id and the real information is in the parent folder. `build_disc_plan()` runs once over the whole file list *before* the per-file loop, because episode numbers are positional and can only be derived from the group: it matches folders like `BUFFY_S3_D1` (show + season + disc) and filenames ending in a `t##` track id, groups every track by (show, season)

   Either half of the folder pattern may be missing: `THE_IT_CROWD_SEASON_4` (no disc) is `DEFAULT_DISC`, and `FIREFLY- DISC 1` (no season) is `DEFAULT_SEASON` — a show that ran one season gets ripped as bare discs, with the season implicit because there was never a second one. The season-less form requires the spelled-out word (`DISC`/`DISK`), not a bare trailing `D2`: with no season to corroborate it, too many movie folders end in a digit for that to be safe. Sibling disc folders of a season-less show still group into one episode run, so numbering continues across discs instead of restarting at 1 on each, drops bonus features via a size check (`_drop_extras()` — any track under `EXTRAS_SIZE_RATIO` × the group median, since episodes in a season run to near-uniform length and one stray featurette shifts every subsequent episode number), sorts by (disc, track), and numbers them by **disc anchor**: an episode's number is its disc's offset plus its track's position inside that disc, so `(disc - 1) * tracks_per_disc + (track - first_track_on_disc) + 1`. Track ids are per-disc and sequential, which makes a gap in them exactly the tracks that were never ripped -- those keep their place instead of shifting everything after them. Counting 1..N across the group did shift them, and worse, a whole absent disc shifted the entire season: The Walking Dead season 3 ripped without disc 1 numbered its disc 2 as episodes 1-4. `tracks_per_disc` is the widest span any single disc spans, not its track count, for the same reason. Returns a `dict[Path, DiscEpisode]` containing *only* the files it recognized — everything else is left to `identify.py`. `DiscEpisode.implied_season_length` carries the highest episode number the group produced -- the season length the rip implies -- which is what makes the count check in step 4 possible.
3. `identify.py` — `parse_filename()` runs `guessit` on the filename only (not the path) to produce a `ParsedName`: media type (`movie`/`episode`), title, year, season, episode. Returns `None` if guessit can't extract a title.
4. `tmdb.py` / `tvdb.py` — take the `ParsedName` fields and query the respective API for the best fuzzy match (`rapidfuzz.fuzz.WRatio` on title, small bonus for year match), returning a `models.MediaMatch`. `TVDBClient` handles its own v4 auth (POST `/login` → bearer token, lazily fetched on first request). TVDB episode lookup pages through `/series/{id}/episodes/default` to find the season/episode; if no matching episode is found, confidence is capped below the review threshold even if the series match itself was good. `search_disc_episode()` is the disc-rip counterpart: it resolves the series, then compares `get_season_episodes()`'s count against `DiscEpisode.implied_season_length` — equal counts mean the disc-anchored mapping spans exactly the season, so it attaches the real episode title; unequal counts mean the mapping is off by an unknown amount, so confidence is capped and no title is attached rather than asserting a wrong one. Both clients reach the network only through `webapi.request()`, never `requests` directly, so retry behaviour is defined once: transient failures (connection and timeout errors, and 5xx) are retried `MAX_REQUEST_ATTEMPTS` (3) times with linear backoff (`RETRY_BACKOFF_SECONDS`, so 2s then 4s), while a 4xx is a real answer (bad key, unknown id) and is returned unretried. The failure it exists for is silent: `main.py` catches a lookup exception, logs it, and moves on, so one dropped request skips that file for the whole run — a transient Wi-Fi stall cost an episode on 2026-08-31. Exhausting the attempts raises (`webapi.RequestError` for a persistent 5xx, the last connection error otherwise), which `main.py` counts as a single failed file rather than aborting the run.
5. `models.MediaMatch` — the shared result type; `needs_review` is `confidence < CONFIDENCE_THRESHOLD` (85, defined in `models.py`).
6. `naming.py` — `build_dest_path()` turns a `MediaMatch` into the final Jellyfin-style path, under the `MOVIES_FOLDER` / `SHOWS_FOLDER` top-level names (`Movies` / `Shows`, matching the library tree at `E:\media` — a differently-named top-level folder builds a second library alongside the real one; these were lowercase until the library moved off `C:\Users\user\Videos` in Aug 2026). Low-confidence matches get `" --needs name review--"` appended to the filename (not the folder name) so they're easy to grep for after a run but still land in a reasonable folder.
7. `convert.py` — `convert_file()` shells out to `HandBrakeCLI -i <src> -o <dest> --preset <preset> --all-subtitles`. Subtitle handling depends on what the source carries, and getting it wrong is expensive. The presets default to a forced-subtitle search, and a disc carrying only a normal full subtitle track has nothing flagged forced, so plain `--preset` silently discards subtitles. Adding `--all-subtitles` selects the track but leaves the preset's burn-in behaviour intact, which renders them permanently into the picture — `--subtitle-burned=none` is what turns that into a passthrough. That works for DVD VobSub, which MP4 can hold. It does **not** work for Blu-ray PGS, which MP4 cannot hold: HandBrake burns PGS in regardless of `--subtitle-burned=none` and reports no subtitle stream in the output. So `probe_subtitle_codecs()` reads the formats out of a HandBrake scan and `keep_subtitles()` allows the request only when every format present is in `MP4_MUXABLE_SUBTITLES` — an allowlist, because an unrecognised format guessed wrong means a film with subtitles burned into every line. When it returns False, `convert_file()` passes `--subtitle none` instead. `probe_height()` scans the source with HandBrake (not ffprobe — the pipeline keeps its single external dependency) and `select_preset()` picks `HANDBRAKE_PRESET` for SD sources (≤576 lines) or `HANDBRAKE_PRESET_HD` above that; an unreadable height falls back to the SD preset, since guessing HD on an SD source costs quality while the reverse only costs time. It also deletes a partial output file if the process exits non-zero *or* if the run is interrupted (Ctrl-C reaches HandBrake too, so it dies mid-write) — and, via `_clean_failed_output()`, removes the destination folder as well when that call created it and nothing landed in it. The folder is made before HandBrake launches, so without this a failure strands an empty movie folder in the library permanently and Jellyfin scans it as a film that plays nothing (`Nightbreed Directors Cut`, Aug 2026). Only a folder the same call created is a candidate and `rmdir` refuses a non-empty one, so an existing film's folder is never at risk from a second cut failing beside it. `is_complete_output()` is the second half of that defense: it judges an *existing* destination by size against its source (`MIN_OUTPUT_SIZE_RATIO`, 10% — far below any plausible encode ratio, so it catches near-empty truncation without second-guessing compression). The cleanup handler only protects runs that die where Python can catch it; the size check repairs whatever slipped through, including stubs left by older versions of the code.
8. `main.py` — ties it together: finds all `*.mkv` under `SOURCE_DIR`, builds the disc plan once, then per file calls `_identify()` (disc plan first, then `parse_filename()` + API lookup; falls back to the raw parsed name at confidence 0 if nothing matches at all — so a file always gets *some* destination path rather than being silently dropped), skips conversion if the destination file already exists *and* passes `convert.is_complete_output()` — a destination that exists but is too small is a partial from an interrupted run, so it's deleted and re-encoded rather than skipped (counted separately as `repaired`). Converts, and logs to both stdout and `logs/run_<timestamp>.log` (gitignored). Run tallies live in `_RunStats`, reported by `_log_summary()`.

   Progress reporting is the script's own, not HandBrake's — `convert_file()` captures HandBrake's stdout/stderr, so nothing of its progress bar reaches the terminal. Each file logs `Processing [i/n]` on the way in and `Converted in <duration>` on the way out, and `_log_summary()` reports total run time. Because a single encode can run for hours with nothing in between, `_heartbeat()` runs a daemon thread that logs `Still encoding <name> (<elapsed>)` every `HEARTBEAT_INTERVAL` (600s) for the duration of the `convert_file()` call — purely off its own clock, so it distinguishes a working encode from a hung one without parsing HandBrake output. It's a `threading.Event.wait()` loop rather than `sleep()`, so teardown is immediate, and it's wrapped in `try/finally` so a failed conversion stops it too.

   The conversion loop runs inside `wakelock.keep_awake()`, which holds a `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` request for the duration. Windows' idle sleep timer keys off user input, not CPU load, so a multi-hour encode would otherwise be suspended the first time nobody touches the machine for the idle timeout. Only sleep is suppressed — the display still blanks. The request is released in a `finally`, so an interrupted run never leaves sleep disabled behind it, and a failed or non-Windows request is logged and ignored rather than aborting the run.

   After a file is handled, `_tag_source()` renames the **source** in place with a `DONE_` or `REVIEW_` prefix (mirroring `naming.REVIEW_MARKER` on the destination side), so `SOURCE_DIR` can be read on its own to see what's been processed. Source files are never moved or deleted — only renamed. Tagging also runs on the "already exists" path, so a run interrupted after conversion self-heals on the next pass with no backfill step. A failed rename is logged and ignored: the conversion already succeeded, so a cosmetic tag must not affect the exit code. Folders are tagged the same way and at the same time: `_tag_finished_folders()` walks from the file's parent up to `SOURCE_DIR`, renaming each folder `naming.folder_prefix()` says has earned a prefix (`REVIEW_` beats `DONE_` beats `SKIP_`, and one untagged track means no prefix at all). This used to be a single sweep after the loop, which meant a run that never reached the end left no folder marks whatsoever — a power cut mid-run on 2026-09-03 threw away the lot while every file tag survived. Renaming mid-run is only safe because `_count_pending()` counts, up front, how many queued tracks sit under each folder: the loop holds absolute paths collected before it started, so a folder is renamed only once its count reaches zero, and the walk goes deepest-first so a child moves before its parent does. The scan root itself is never renamed. `identify.parse_filename()` strips the prefix before running guessit, and `discfolder`'s track regex matches on the trailing `t##`, so re-scanning a tagged library identifies identically.

## Known limitations

`identify.py` only parses the **filename**, not the parent folder. It assumes filenames carry a usable title/year/SxxExx (typical scene-release naming). Ripped-disc libraries, where the meaningful info is in the folder name and the filename is just an opaque track id (e.g. `BUFFY_S3_D1\C1_t00.mkv`), are handled separately by `discfolder.py` (step 2 above) — but only when the folder matches the season/disc pattern *and* the filename ends in a `t##` track id. Anything else still falls through to `parse_filename()` and, failing that, the review-flagged fallback.

Disc-anchored episode numbering is still a heuristic, and its accuracy now depends on two things: every disc holding the same number of episodes, and each disc's *first* episode having been ripped. A gap anywhere else is harmless — the track ids carry it — but if track `t00` of a disc is the one missing, that disc's anchor slides and every episode on it is off by one. The validation is `implied_season_length` against the season's real count; when they disagree the pipeline can tell you *that* the mapping is wrong and not *where*, so it flags every file in the group at confidence 60 with no episode titles rather than guessing. A duplicated track, an extra that happens to be episode-length, or a disc with an unusual episode count all land here and need a human.

The count check is a count, so two errors in opposite directions cancel and it passes. Buffy S6 is the worked example: disc 1 carries the two-part premiere as one 1h27m track (one track short) and disc 3 carries a 59m extra that survives the size filter (one track long), giving 22 tracks for 22 episodes. Nothing flags, and episodes 2–11 come out shifted by one. Track *duration* is the signal the pipeline doesn't use and a human should: run `HandBrakeCLI -i <file> --scan` across a group and anything that isn't the season's normal episode length is either a merged multi-parter or an extra.

TVDB's `/episodes/default` ordering is the aired order, which is not always the order the discs are laid down in. Firefly is the standard counterexample — the discs run in the intended order (`Serenity` first), while the aired order TVDB returns puts `Serenity` at 11 — so a complete rip would still be titled wrongly. Positional numbering is only meaningful against a season whose disc order and aired order agree.

The size filter cuts on relative size, not content, so it only catches extras that are markedly shorter than an episode. A feature-length documentary or a "play all" track spanning a whole disc is longer than the median and survives the filter — the count check then flags the group. It also assumes uniform episode length within a season; a season mixing 22- and 44-minute episodes could see the short ones dropped (they'd still convert, just via the review path).

Episode *order* within a disc is assumed to follow track number. Discs that lay tracks down out of broadcast order will number confidently and wrongly — the count check passes, so nothing gets flagged.
